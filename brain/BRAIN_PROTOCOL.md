> 它把 `aorta_digital_twin` 项目 28 天无人值守运行中被用户逐条强制要求的「最高逻辑」

## §1 架构层：权威如何成立

> 本节回答"凭什么这份文件说了算"。**没有这一层，其余条款都只是建议。**

### U1 最高逻辑文件唯一化 + 冲突规则

- 项目根放**一份**自包含的最高逻辑文件（ASCII 文件名，如 `ULTIMATE_PROTOCOL.md` / `BRAIN_PROTOCOL.md`）。
- 文件头部必须写死四条：① 生效范围（本仓库内一切工作 + 任何未来会话，无论是否带历史上下文）
  ② 冲突规则（会话记忆/笔记/总结/口头约定与它冲突 ⇒ 以它为准）
  ③ 变更规则入口 ④ 校验器命令。
- **判据**：任何人读完文件头部 20 行，就能回答"谁说了算、怎么改它、怎么验它"。
- **该失败时会失败**：若文件只存在于某次对话的总结里 ⇒ 换一个会话即失效（这正是本条要消灭的形态）。

### U2 哈希登记 + 机器门控

- 权威文件的 sha256 登记在盘（`outputs/audit/*.registry.json`，含 `generated_at` 与 `produced_by`）。
- 一条命令跑完全部门控，输出**单一判决**：`PROTOCOL_GATE: PASS` / `FAIL`，并落盘 JSON 证据。
- 门控至少含五项：① 本文件哈希 == 登记哈希 ② 文件内引用的路径/命令真实存在
  ③ 继承副本哈希 == 声明的源哈希 ④ 所有 `.md/.json/.py` **无 BOM** ⑤ 索引与正文的条目集合一致。
- **判据**：`引用了某文件/命令` ⇒ 该文件/命令必须被门控实际检查过存在性。
- **该失败时会失败**：门控必须自带**阴性对照**——篡改一个字节，它必须报 FAIL（见 §11）。

### U3 变更程序（唯一合法修改路径）

四步，缺一即违规：

1. 先写**新版本文件**（新文件名或新版本号），**保留旧版本**；
2. 跑 `--register` **更新登记哈希**；
3. 在 `docs/` 写一份**变更说明**：为什么改 / 改了什么 / 影响哪些结论；
4. `git add` **显式路径**并提交。

- **未走完四步的任何修改 = 违规**，门控报 FAIL 并写告警文件。
- **判据**：任何"改了规则"的动作，都能被外部检查到「新版本文件 + 登记 + 变更说明 + 提交号」四件套。
- **禁止**：就地改权威文件而不留旧版本；用 `git add -A` / `git add .` 提交（会把别人正在写的中间版本卷进来）。

### U4 落盘判定四条（机器可查）

一件工作只有**同时**满足下列四条，才算"已落盘"：

1. **有文件**：在 `docs/`（理论/方法/结论）或 `outputs/`（证据）或 `code/`（可复跑仪器）中有确定路径；
2. **有来源**：产物内带 `produced_by = {script, script_sha256, generated_at}`；
3. **有校验**：仪器自带 **KAT（自检）** 与**阴性对照**（能证明自己真的在测那件事）；
4. **有索引**：被登记进总账，**由脚本自动生成，禁止手写**；来源/校验先落原件，再按 U29 的显式 changed paths 更新与核验，文件数或 mtime 不等于登记成功。

**违反示例（一律不合格）**：只在回复里给出的数字；只在记忆笔记里的结论；没有 KAT 的仪表；
没有证据 JSON 的"通过"；把"假定"写成"实测"。

### U5 自检入口可交接

- 权威文件末尾必须给一段**可复制粘贴**的自检入口（跑哪几条命令、按什么顺序读哪几个文件）。
- 配一句**接管顺序**：先核目标 root/cwd/记忆绑定 → 按 U29 读有界活跃目录 → 定位并回读本任务权威原件/清单 → 校验需要依赖的门控 → 执行；协议哈希 PASS 只是必要条件，不是完成恢复。
- **判据**：把这段命令块交给一个**没有任何上下文**的新会话，它能自己跑起来并说出"现在到哪一步"。

## §2 执行层：每轮怎么跑

> 本节是"每轮第 0 步到收尾"的完整动作序列。**任何一条被跳过，该轮结论都不算数。**

### U6 每轮第 0 步先读主线

- 项目实质性工作每轮及压缩/换模型恢复后，主线的**唯一权威文件**（范围、流程、当前进度）必须被**实时读取**；由 U29 有界目录定位相关原件，不全文注入——**不复制、不硬编码**，
  文件一改，第 0 步的输出就跟着变。
- 任何"我该做什么"的问题，标准答案是「**去读那个文件**」，不是凭记忆回答。
- **判据**：存在一条命令，每轮打印出「主线 + 现阶段范围 + 流程与进度 + 纪律 + 下一步」。
- **反向事故（来源）**：曾因"忘了主线是什么"只做了主动脉主干、漏掉分支与多器官，
  而范围文件里**早已写明**；也曾把 2D 验收图当成交付物（真交付物是能进求解器的 3D 模型）。

### U7 先遍历资产 + 工具先例三形态

- **任何节点开工前必须先遍历资产**（沿用已有要求；具体有界恢复/缓存契约见 U29，不要求每轮全盘扫描），确认四件事：① 已有交付物是什么（文件路径）
  ② 哪些结论**已被后续审计推翻** ③ 哪些是"试过但失败"的路线 ④ 还缺什么 ⇒ 才允许动手。
- **禁止默认"从零开始"** —— 违反会造成重复劳动与**被推翻结论的二次传播**。
- **工具先例三形态**（用任何方法/工具前先 `grep` 仓库 + 查大脑索引）：
  ① 仓库里有"试过且**不可用**"的记录 ⇒ 直接用那个结论，**别再试一遍**；
  ② 仓库里已有**正确实现** ⇒ 直接复用；
  ③ 仓库里有实现但**没人用** ⇒ 不算数，须接上或标注（见 U26）。
- **判据**：`grep -rn "<工具名或算法名>" code/ docs/` 与索引查询，必须出现在"选用某工具"的理由里。

### U8 遇困难 ⇒ 第一动作是查文献

**触发**（满足任一即触发，**不等到"卡死"**）：结果不理想 / 逻辑不通 / **我准备靠推理或"尝试"来解决**（危险信号）。

**动作（按序，第一条必须在改代码之前）**：

1. **查文献**（外部：原始文献 OA 全文优先，付费文献读摘要并标"不可核验"）；
2. **在仓库内先查**（成本更低）：索引查询 · `docs/*.md` · `code/*.py` 同类脚本；
3. 只有前两步都无解，才允许自行设计方法，并在产物中**标明"无文献依据"**。

- **判据**：遇到困难的第一个工具调用是检索，而不是"改一版试试"。
- **实测依据**：某轮凭算术推出"要放粗网格"方向错；下一轮查文献得 RBF 光滑插值，
  照改后指标改善 **163 倍** ⇒ **一次查文献 > 三轮猜测试错**。

### U9 禁止空转轮 +「推进」三口径

- **只有下列三者才算推进**：① 新增产物（文件落盘）② 新增实测数字 ③ 需用户决策。
- **单纯重复上一轮的状态表不算推进 = 空转**。自检：本轮回复若与上一轮实质相同 ⇒ 本轮应一行带过或直接暂停。
- 待命轮**不落盘**：只做心跳与按需巡检，**不写任何文件、不 commit**；禁止"为写而写"。
- 每次落盘前自问一句：「**这一步有没有实质产出？**」没有就不写。
- **反向事故**：曾连做约 25 轮空转，既无产出又把系统盘 Temp 顶到 **11 GB**。

### U10 上下文节约与委派

四条执行口径：

1. **能放到子代理就放** —— 长任务/重上下文任务用 subagent 承载；派活时任务书**必须自包含**（子代理看不到主对话）；
2. **不需要做的就不做** —— 不制造动作、不做无价值轮询、不重复已验证的事；
3. **能暂停就暂停** —— 在等外部产物期间暂停 goal，**不要逐轮报状态表**；
   注意暂停态只有用户能恢复 ⇒ 暂停前必须在正文里告知用户怎么恢复；
4. **来了回报再自主恢复** —— 子代理回报 / 新产物落盘 / 需用户决策时才回到主线动手。

- **判据**：主对话里不出现"派活后原地等"的轮次堆叠。

### U11 汇报四段式 + 唯一事实来源

每轮回复**末尾必须**列「当前需要用户操作的事项」，四段式：

1. **只有你能做** 2. **可选/可延后**（附我的绕法） 3. **需要你拍板**（附我的建议） 4. **已闭环、无需操作**

- 排序：**卡住下游最多者优先**；**30 秒能解锁一条轨道的永远排第一**。
- **唯一事实来源 = 项目的「用户待做清单」文件**；**禁止凭记忆列举**（凭记忆列举 = 编造）。
- 用户已授权"需拍板项允许代理按最优方案自主进行" ⇒ 拍板项默认**给建议值并执行**，
  只把**代价高/不可逆**的项标出来请求确认（见 U14）。

### U12 存储分流与异盘备份

- **存储分流**：大产出写**工作盘**（避免占用系统盘）；小产出写仓库盘；**系统盘禁写**；**临时文件同规**。
- **写大产出前先估算体积并报给用户**；禁止不经估算就往任何盘写大文件。
- **临时文件**：每次命令调用显式设置 `TEMP/TMP/TMPDIR` 到工作盘/仓库盘；计划任务的动作也必须显式设置；
  **每轮收尾清理**；阈值告警（超过阈值立即清理并记录）。
- **珍贵产物必须异盘备份**：
  - 入选判据**先写死**再跑：**P1 生成代价高**（重建需 >1 CPU-day）· **P2 不可从上游廉价再生** ·
    **P3 体积可控**（单件 ≤ 备份盘余量）；
  - **校验口径**：复制后**逐文件比对 size + sha256**（活体 vs 备份）；**任何不一致记 FAIL 并如实上报，不得掩盖**；
  - ★ **原件不删** —— 那是**第二份**，不是把东西迁走。
- **反向事故（本条的由来）**：临时文件累计约 **115 GB** 把系统盘写满；
  工作盘根下出现 **45 个 `found.000`–`found.044`**（chkdsk 恢复残片）⇒ **只存一份不安全**。

### U13 工具路由与无 BOM 写盘

- **命令执行**：一般命令/构建/git/管道用 bash 工具；**报错就在 bash 里改，不许换 shell 重试**
  （换 shell = 把一次语法错变成两套语法错）；Windows 原生功能才用 PowerShell。
- **文件操作**：优先专用文件工具（读/搜/找/批量替换）；**精确改动**用 literal 替换（最小 diff）。
- **长脚本（>1 KB · 含 heredoc/引号/非 ASCII）先写成文件再调用**，禁止把多行脚本塞进命令行参数。
- **写盘**：`.py / .json / .md` 一律用**能写出无 BOM UTF-8**的方式（Python `open(..., encoding='utf-8')`）；
  ★ **禁止 PowerShell `Set-Content -Encoding UTF8`** —— 它会写 UTF-8 BOM ⇒ 下游 `json.load` 报
  `Unexpected UTF-8 BOM`、`ast.parse` 报 `U+FEFF`（本机已有实例：一个配置文件被这样写坏，其全部调用方同时挂掉）。
- **判据**：改完的 `.py/.json/.md` 均有 before/after sha256 打印，且 `raw[:3] != b'\xef\xbb\xbf'`。

### U14 授权注入与两条红线

- 用户下达"**其余按学术标准最优化方案执行**"这类总攻令时 ⇒ **覆盖此前所有"需用户拍板"项**，不再逐条征询。
- 但**两条红线不变**：
  ① **判据不得为通过而放宽**（口径修正仍须走变更程序并留档）；
  ② **不可逆的对外动作 / 物理资源 / 只有用户能做的专业判读**，仍归用户。
- **判据**：读一条"自主执行"的授权，能同时说出它**覆盖什么**与**不覆盖什么**。

### U15 纪律必须回到底层（再生机制）

- skill 是**静态文本**，无法自动感知别的会话改了什么 ⇒ 唯一可靠做法是
  「**权威正文文件 + 一个能重新生成 skill 的脚本**」。
- ★ **溯源（如实标 · 2026-10-15 第二方复核指出）**：本条**不是**从被继承的 `ULTIMATE_PROTOCOL.md`
  提炼的，而属**跨源合成**——**机制**（权威正文 + 再生脚本）来自 `brain` skill 自身既有的 §6.2；
  **纪律要求**（新规则先落盘再引用）来自源文件 §5.5；再生链本身是本仓 2026-10-15 新建的
  （源文件中 `grep -ic skill` = 0、`DISCIPLINES_CORE` = 0）。**不得**把本条说成"源文件原有"。
- 任何 agent（含子代理）发现新纪律或修正旧纪律时**必须**：
  ① 把纪律追加到**权威层**（本文件 U 层）与**纪律层**（`DISCIPLINES_CORE.md`）；
  ② 同一轮内同步到项目大脑；
  ③ 运行同步脚本再生 skill，使**下一个会话/子代理读到的是最新版**；
  ④ **不得只写在对话里**（对话会被压缩/清空，纪律会丢）。

## §3 判据层：怎么才算"验证过"

> 本节是整个协议**最贵的部分**：主动脉项目 28 天无人值守运行换来的失效清单。
> （规模数字据 **2026-10-15 实查**、**非来自被继承的协议文件**，取自主动脉仓
> `$AORTA_PROJECT`：其 `git rev-list --count HEAD` = **1,237** 次提交；
> 其 `outputs\ASSET_LEDGER.json` 的 `assets` = **7,831** 件登记资产。）
> 它们的共同特征只有一句：**不报错、看着对、只有专门的"账目"能抓。**

### U16 判据准入门：先在真实数据上测通过率

- ★★ **任何"门控/判据"在用于新产物之前，必须先在真实数据上测通过率。**
- 若**真实数据**都过不了（或通过率远低于合理值）⇒ **是判据错，不是数据错** ⇒ 先修判据。
- 判据的**真实数据通过率**必须与产物的通过率**一起**写进质检报告。
- **判据自身的验证是强制项**，不是可选项。
- **实测**：把"10 个 u 全单调"当判据 ⇒ 真实 693 例只有 **2 例**满足；
  改为**解剖组序**判据 ⇒ 干净例 **238/238 = 100%** 通过。

### U17 没有反例的检验不算检验

- 每个环节的质检**必须包含**：① **正例**（本环节产物应通过）
  ② **反例/阴性对照**（人为破坏的输入**应被拦下**）③ **自检 KAT**（写进脚本、一键复现）。
- ★ **反例必须"越界"**（gross error）；用"中等扰动"做反例 = 用错判据。
- ★ **对照无效 ⇒ 该判据结论作废**，不得引用其数字。
- ★ **真空真**：任何门禁/判据在「**被测对象数为 0**」时必须 **FAIL**；
  自检问句：**「我把被测对象清空，它还会通过吗？」** 会 ⇒ 该判据在空集上无效。
- **聚合布尔必须与逐例明细交叉核对**：只有 `PASS` 而没有子字段 ⇒ 视为未验证。
- **判据事前冻结**（JSON + sha256）；**FAIL 照记**；**不许事后回调容差**。
- ★ 本条与既有条目 **W2（真空真）**、**Z3（聚合布尔交叉核对）** 是同一家族：那两条是本条的两个具体形态，
  已在 skill 纪律索引中单列，此处只作汇总，不重复定义。

### U18 引外部数字三问 + 机制/数字分离判

- 凡别的线/子代理报来的**关键数字**——尤其**据以推翻既有判断**的数字：
  ① 先问：这个数量的是**哪个对象**·**什么口径**·**哪次运行**？（单位与量级要对得上）
  ② 必须能**独立复现**到同口径；复现不出 ⇒ **不得引用**，并让对方澄清口径；
  ③ ★★ **机制与示例数字可分离时，必须分开判**：
  **机制成立 ⇒ 采纳机制；数字复现不出 ⇒ 不采用数字。**
  一起接受 ⇒ 把错数字写进报告；一起否掉 ⇒ 会误把已被推翻的旧判断复原。**两种都错。**
- ★ **同一日志/文件里可能有多次运行** ⇒ 引用时必须连【**时间戳 + 运行序号**】一起核。
  （既有条目 **Z4（回原始记录复核）** 是本条在"引用既有文件"一侧的形态，此处不重复定义。）
- **实测**：某线报"点云 0.8 mm 栅格化碎成 301 块"，复测得 22（差 13.7×）；
  但"栅格变粗则分量单调不增"11/11 成立 ⇒ 裁定：**机制采纳、数字否掉**。

### U19 量的对象必须 = 被评价的对象

- ★ **下任何"误差 / 错位 / 不对劲"的结论前，先问：我量的是什么对象？它是不是用户/下游真正要看的东西？**
- **形态一：合成样本的真值必须是它自己的生成参数。**
  拿一个真实例当合成样本的真值 ⇒ 量到的是"**个体差**"，不是"误差"。
- **形态二：口径三问** —— **同部位？同口径（半径/直径/面积/段平均）？同单位？**
- **形态三：自证式判据** —— 问「**我把设置改坏一点，它还会通过吗？**」会 ⇒ 判据作废，改做敏感度检验。
- **形态四：同源审计的虚假安全感** —— "图像↔图像"的自洽审计**结构上不可能**发现跨表/跨段/单位混用
  ⇒ 结论里**必须写明"本审计不覆盖 X"**。
- **形态五：单值不构成验证，且两种口径必须并列报出** ——
  ★ 任何"解可信"的结论必须**至少两条独立判据同时成立**，**单值不许当结论**
  （实例：单个位移峰值曾给出 0.036，而真值 0.052、另一独立判据为负 ⇒ 伪模态）；
  ★ 同一物理量存在两种口径时（如"跟随载荷"与"死载荷"），**结果表必须并列给两列，绝不混用**；
  ★ 报告离散误差必须来自**收敛研究**（网格/步长序列 + 外推），外推值一律标注 `EXTRAPOLATED`。
- ★ 每条"验收类"判据都必须在**判据名或输出**里写明【它量的对象是什么】。

### U20 无符号量 + 有符号操作 = 假改善

- ★★ **当量具的输出无符号、而操作有方向时，两者必须配对使用**：
  · 无符号距离（最近点距离 / KD-tree / 面距） **＋** · 有符号的判内量具（绕数 / 内外判定 / 方向归一后的法向点积）。
- **只报前者，则"推出去"与"推更深"在数字上不可区分。**
- 凡"把某物推出去/拉进来/贴合到"这类带方向的操作 ⇒ **写操作前必须先量一次带符号的里外关系**，
  并在报告里**同时给出**无符号距离与有符号穿透计数两组数。
- **实测机理**：某修复脚本用 `dot(u,n) < 0 ⇒ n ← -n`（推到"当前所在的一侧"），
  而最近点距离**无符号** ⇒ 对已在内部的点，"往外推 margin"等于**沿内法向推得更深**：
  **距离数字变好，穿透计数从 67 反弹到 1193。**

### U21 外部真值核查是硬门，且必须闭环

- ★ **外部知识/标准核查不是可选项，是硬门**：每条交付在出具前必须过"与权威外部信息核对"这关。
- ★ **核查必须闭环到修复**：核对出 FAIL ⇒ **必须修**。
  若判据确有缺陷 ⇒ **先修正判据、用修正后的口径重跑，再判 FAIL/PASS**；
  ★★ **不得让"判据缺陷"成为 FAIL 的免罪符** —— **查出来不修，等于没查**。
- **来源纪律**：外部基准表每条**必须带可点开的 URL** 与**证据等级**（**E3** = 读过正文带页号/表号；
  **E2** = 仅摘要）；**无 URL / 未标等级 ⇒ 该条不得用于 PASS 判定**；查不到就**标 ND，不许凭印象编**。
- **用途边界**：外部来源**只作核对与佐证**，**绝不允许喂进模型 / 训练 / 降维 / 形状来源**；
  产物必须明写 `external_geometry_used = False` 之类的断言，缺断言不予验收。
- **不得自证**：交付件出具人不得只自证，**必须由第二方用独立口径复核**。
- **每轮必须报告核查状态**（逐类 PASS/FAIL/ND）；★ **ND 也要报，不许省略**——省略就无法区分"没问题"与"没查"。
- **反向事故**：核验线早已报"包裹关系 FAIL"，而 lead 以「判据措辞本身不成立」为由把它标成"待人工判断"放过；
  用户复核时当场指出"**肝脏跑到了主动脉后面**"。

### U22 亲眼看图是硬门

- 凡产物含**图像**（渲染图 / 切片 / 蒙版叠图 / 曲线图）⇒ **必须实际读图**，**不得只看它的自检文字**。
- ★ **看图必须问对问题**（五条，缺任一条即**看图无效**）：
  ① 左右是否正确 ② 解剖/结构位置是否正确（在不在目标结构内部）③ 分支与主干是否连续
  ④ 每个结构是否真的可见可辨（颜色 / 不透明度）⑤ 文字标注是否可读。
- ★ **每次看图必须覆盖此前漏过的维度**，并在质检件里**写明"这次看了哪几个维度"**。
- ★ **图的验收必须量数**（肉眼只作触发，结论必须由冻结判据跑数）：面片抽稀率 vs 输入面数 ·
  是否开启抗锯齿 · 像素尺寸下限 · **几何文件 sha256 是否未变**；**看图前先核对文件时间戳/大小**确认不是旧版。
- ★ 二维投影可见性（像素命中）**是弱证据**，不得代替三维几何判定；两者都要报。
- **严禁**：只跑判据、只读 JSON、只比 sha256 就报"通过"——那正是多次翻车的共同根。

### U23 不许为过判据毁交付物

- **假改善比真缺陷更坏。** 任何"为让判据变绿"而改几何/改口径的动作，
  必须**同时**报【判据值】与【被牺牲的量】；若被牺牲的量越过任一维度 ⇒ 判**不可用**并**回滚**
  （不许写"已修好"）。
- **修后必须量数并与修前对比**，**至少不劣于修前，否则回滚**；迭代轮数用尽仍未达标 ⇒ **如实报未达标**，不许含糊。
- **反例必须留在盘上**（把失败的尝试当资产报出来，而不是删掉）。
- **实测反例**：各向同性核平滑把自交降 −91%，但体积 +11.9% ⇒ 判不可用；
  逐索引精确钉住能让长度差趋零，但圆度 0.64→0.28 ⇒ **拒绝使用**（宁可留着已定位的病灶）。

### U24 单例反例不得推广成普适结论

- 凡结论形如「**X 不成立 / X 是错的 / 应改成 Y**」，必须写明【**对哪个对象 / 哪个案例 / 哪个口径**不成立】。
- **不得从单例反例推出普适结论**；★ 若声称普适，**必须给出跨例统计**（如"N 例中 M 例不为 X"）。
- **实测**：某线在单个案例上实测体素尺寸，据此判定「"0.75 mm"口径不成立」，lead 照抄；
  另一线实测同批另一例 zooms = 0.75 ⇒ **两个结论各自对本例成立，都不能推广**。

### U25 量具三查

**上量具前，把这三条各答一句写进脚本 docstring**；任何一条答不上 ⇒ **不许拿它的输出下结论**（记 `NOT_OBTAINED`）。

1. **原理对不对** —— 这个算法**在数学上**适用于我的输入吗？
   （事故：用"伪法线有符号距离"判内外 ⇒ 报出"8 根血管穿骨、最深 −464 mm"，而骨头只有约 180 mm 宽；
   被它自己的阴性对照拦下。）
2. **本仓有没有"已判不可用"的先例** —— 见 U7 三形态。
   （事故：推荐某工具，而仓库里早有注释写明它对本项目的面"恒返 False、不可用"。）
3. **复杂度能不能跑** —— 先算【点数 × 面数】量级，并**先在小样本（如 1000 点）上试跑计时**，再决定是否上全量；
   能用抽样的就别用全量（要占比时，抽样足够）。
   （事故：全量算立体角 ≈ 1.8e10 次/对 ⇒ 跑了 40 分钟无输出而立项就需数小时。）

### U26 产物必须登记下游消费者

- 凡产出物（脚本 / 参数文件 / JSON / 数据集），必须在登记处写明★【**下游消费者是谁**】
  （哪个脚本 / 哪个流程 / 哪条线在读它）。
- 无消费者的产物 ⇒ ★【**要么把它接上，要么显式标注"未接入"**】；
  ★【**不许留一个"看起来做完了、其实没人用"的东西在库里**】。此处要求标明未接入，不授权删除；无消费者本身不是无用证据（见 U29）。
- 每个环节/线的收工汇报里，必须有一行【"**本产物谁消费**"】；答不上来就是没做完。
- **实测**：项目早已实现"空间变化外包络"并产出参数文件，但全仓 grep **只命中它自己**
  ⇒ 它从未进入任何求解 ⇒ 这才是"算例里还留着旧常数"的**直接原因**：不是没人想过，是**做出来的东西没人接**。

### U27 不得把【计划】写成【现存】

- 凡在汇报里写"某产物**存在 / 已做 / 可看**"，必须**先上盘核实**（列目录 / 读文件）；
  尚未存在的，一律写明「**计划中 / 尚未产出**」。
- ★ 与"**标签 ≠ 实质**"同族：两者都是【**把意图或自称当成了事实**】。
- **实测**：把"看验收图"写进"只有你能做"清单，而当时图还没生成，用户据此去找、扑空；
  另一例：据元数据 `description` 断言"生成方法是两例插值"，而实际链路用的是全库联合采样。
- **同类**：**"假定"不得写成"实测"**；**"插件文档口径"不得写成"本项目实测"**（引用时须标注口径与是否复跑）。

### U28 smoke ≠ 科学结果

- **产物必须能自证类别**：工具链验证（smoke）产物单独目录、文件名含标识，
  且文件内必须有一行 `"verdict_scope": "toolchain-smoke; NOT a scientific result"`。
- **科学仿真的准入条件（缺一不可）**：
  ① **边界条件**必须能回答"取自哪个既有文件"——**不许自造数值**；
  ② **模型设定**必须能回答"取自哪个权威设计文件"；
  ③ **验收判据（KAT）必须已冻结**。
- **每轮自问**：「我这个数，**边界条件来自哪个文件**？**模型来自哪个文件**？**判据冻结了没有**？」
  —— 三问有一问答不上，本次就只是 smoke，**不许进结论**。
- **实测**：自造了一套求解器案例，用自己拍的入口速度与出口压力；而边界条件面集**早已由某脚本产出 7/7 例**
  ⇒ 两重错：重复既有资产、且产物形式上像"科学仿真"、实质只是验证工具。

## §4 恢复与收尾层：资产是上下文的可核对入口

### U29 资产目录驱动的每轮恢复与收尾契约

**来源与边界**：2026-10-25 用户要求把既有 U7「先资产后工作」与 U4「来源/校验/索引」落实为跨会话恢复契约；不是宣称此前没有规则。此条不替代项目权威原件，也不扩大读写授权。

1. **先核绑定**：明确目标项目绝对 root、当前 cwd、宿主记忆命名空间；三者可能不同。使用已确认 root 的绝对入口，不能由 cwd/记忆猜项目。错绑时不写该空间的项目事实；证据留在目标项目授权目录，绑定不明只阻止依赖绑定的动作。
2. **实质轮与恢复轮**：开始修改/决策前，读取有界活跃目录中的主线、关键原件路径、当前状态、缺口/下一步及失败/被推翻线索。恢复热读总预算 **≤6000 字符**，已加载的入口不重复注入，不全文灌大目录/巨型纪律。检索索引只负责定位；论证、数值、代码输入必须打开原件核对来源、口径、版本和验证状态。普通概念问答、无资产变更的解释不触发扫描/写盘。
3. **缓存与证明**：目录/索引是可再生派生缓存，不是第二份事实权威。记录 source paths、内容 hash、生成器版本/hash、验证状态及覆盖范围；有界 brief 只读且拒绝陈旧。新鲜度要核对显式 changed paths 与相应源指纹，**不得以 mtime、件数或缓存自报 fresh 代替**；未列入监测集合的变化不声称已覆盖。
4. **先原件后派生**：有产物或事实变更时，先落原件、来源/hash 与校验（U4/U17）；再沿项目既有 **扫描→台账→检索索引** 链收尾，传显式 changed paths，逐项确认收录、指纹和验证结论，最后重读 brief/协议门。任何一步失败，禁止依赖失败资产的后续动作或“已收尾”声明；不以修改时间/总件数凑通过。无变更不制造扫描与写盘。
5. **当前/历史分层**：活跃层只承载当下需要的入口；不再承担当前用途的索引可移出活跃层，但历史层保留原路径/hash、替代指向、退役原因和失败经验，并可检索。**不删除源件**；不得仅按新旧、年龄或“没有消费者”判为无用，也不得把被否证结论无标注地重新放回当前层。
6. **失败分类与有限补查**：OFFLINE=盘/源暂不可达；MISSING=已确认位置可达但文件不存在；STALE=源/缓存版本或指纹不一致。分别报告原因与依赖面，不能把离线判成缺失/无用。先查活跃索引，再按任务词查历史/限定路径；每批至多 12 命中，最多两批无新证据就报告缺口，禁止扩成全盘盲扫。修复/重新连接后必须复验，再恢复依赖动作。
7. **跨模型恢复承诺**：文件与入口提供可恢复性，不保证任何模型一定遵守。宿主必须实际加载项目入口（如 AGENTS/CLAUDE）或 brain；应记录入口执行和验证结果，未加载/失败不可把“hash 通过”说成接管完成。跨模型、跨宿主未实测部分如实标明。

## §11 门控口径与阴性对照

`code/1300_protocol_gate.py` 的六项检查（全部落盘进 `outputs/audit/protocol_gate.json`；
**判决行永远是输出的最后一行**，供流水线直接读取）：

| 项 | 检查 | 该失败时会失败（对照） | 覆盖边界（**不**检查什么） |
|---|---|---|---|
| ① | 本文件 sha256 == 登记哈希；**且**登记凭据里的门控脚本 sha256 == 当前脚本 | 改一个字符 ⇒ FAIL（KAT 用篡改副本实测，不动本体）；门控被替换而未重登记 ⇒ FAIL | 不校验登记文件自身是否被改写（由脚本哈希间接锚定） |
| ② | 本文件**反引号内**的仓内路径（`code|docs|outputs|_inherited|references/` 前缀、带 `.md/.py/.json` 后缀；含通配符者按 glob 命中）真实存在 | 把某个引用路径改成不存在的 ⇒ FAIL | ★ **不检查命令**，也不检查无前缀的裸文件名 |
| ③ | `_inherited/` 副本 sha256 == 凭据声明 == **活体源文件**（源可达时重读源） | 副本被改一字节 ⇒ FAIL；**副本与凭据同时改写** ⇒ FAIL（源锚点）；源不可达 ⇒ **显式降级**并写明可被伪造 | 源不可达时本项不再提供抗伪造性（会打印降级说明，**不静默**） |

| ⑤ | `ULAYER` 索引 id 集合 == `UDETAIL` 小节 id 集合（**空集亦 FAIL**） | 删一个索引行或一个小节 ⇒ FAIL | 只验 id 集合，不验逐字内容 |
