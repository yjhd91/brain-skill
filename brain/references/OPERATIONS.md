## 1. ★★★★ K 系列：自主推进 + 主动求证（最高优先级）

| 规则 | 可执行判据 |
|---|---|
| **K1 自己能做的，一律做完** | 只要不涉及①用户的物理资源/账号/审批 ②用户才能做的专业判读 ③不可逆的对外动作 ⇒ **不问，直接做** |
| **K2 只在「确定性结果」后咨询** | 确定性结果 = 已完成、可复现、有证据，且需要用户做**取舍**。**禁止**把"我卡住了/要不要试试/你觉得怎么办"这类**未完成态**抛给用户 |
| **K3 困难 ⇒ 主动联网求证** | 困难与逻辑不通**不是**问用户的理由，而是**检索信号**：多关键词检索 → **下载并阅读原文**（OA 全文优先；付费文献读摘要+被引并标注"不可核验"）→ 找**可直接使用的数据/代码/示例**，而不是从零猜 |

**自检问句（准备提问前先问自己）**：
> 「这件事我能不能用代码/数据/文献在本机做完？**如果能 —— 就不该问**。」

**仍然必须问用户的 4 类**：①物理资源/账号/审批 ②专业判读 ③不可逆对外动作 ④价值判断型取舍
（第 ④ 类必须**先给出做到极致的草案**，用户只需"改/批"）。

## 2. ★★★★ 算法优先：结果不符时先怀疑算法，不要先归因于"标定/现实差异"

出现"结果与预期不符"时，**必须按顺序排查**，禁止跳到解释：

1. **单位/量纲**（本项目高发：mmHg↔Pa 差 1000 倍；`Eh = ρDc²` 被误写 `2ρDc²`）→ **写显式量纲自检**
2. **索引/坐标系/方向**（左右镜像、行列转置、affine 方向）→ 用 affine 推导，**禁止硬编码轴翻转**
3. **口径版本**（跨版本未换算；"队列里有 N 例 X"必须标明**表版本 + 阈值**，并**让脚本去数**）
4. **守恒律自检**（体积守恒、能量守恒、质量守恒）—— **最廉价的独立判据，不需要文献、不需要标定**
5. **算法缺陷** vs **参数标定**：先证明是哪一个，再动手改。**怀疑某参数被"调过"时，先查它的出处，再决定改哪个**
6. 以上都排除后，才允许讨论"模型-现实固有差异"

## 4. ★★★ 清单纪律：清单是唯一调度权威

- 维护项目根目录 `CHECKLIST.md`，每项含：**任务 / 依赖 / 状态 / 为什么在这个位置**
- **每次任务开始前，以清单顺序为准**；**禁止**跳来跳去（"一会做 T3-2 一会做 TS"会失控）
- **排序三判据**：①依赖 ②可并行性 ③**风险-信息量**（de-risking 优先：先做"失败会推翻整体计划"的那一项）

## 5. ★★★ 无人值守运行的四条保护（每条都源于一次真实事故）

| 规则 | 要点 |
|---|---|
| **内存安全事前告知** | 启动长任务前，必须**主动告知用户**：预计峰值内存、持续时间、**预计多久占满内存**、以及是否可中断。阈值：达 60% 提醒，90% 立即处置 |
| **长任务必须脱离作业树** | 用 `Start-Process`（Windows）等**独立进程**方式启动；**控制器里 `Popen` 拉起的子进程会随控制器退出被连带杀死**（本项目因此静默死亡 2.5 h） |
| **自愈看门狗** | 常驻脚本每 10 min 自检："进程还在吗 / 进度还在动吗 / 还剩多少活"，**死了就自动重启**；全量完成则跑收尾质检后退出 |
| **检测失败必须"宁可漏报"** | 判定"是否有任务在跑"时，**默认行为必须是"不动"**。用不可靠手段（如 `wmic`）取进程列表 → 超时返回空 → 误判"没在跑" → **重复启动 ⇒ 并发打爆内存**（本项目实测 29.3/31.7 GB） |

**并发红线**：一个重任务同时只允许一个实例（用锁文件 + PID 存活检查）。

### 6.1 任何 agent（含子代理）发现新纪律或修正旧纪律时，**必须**：
1. 把新纪律**追加**到权威层 `BRAIN_PROTOCOL.md` 的 U 层（改它必须走 §9 四步：新版本文件 → 重登记
   → `docs/` 变更说明 → 显式路径提交）；
2. 同一轮内同步**纪律层** `references/DISCIPLINES_CORE.md`（带日期 + 触发事故 + 可执行判据）
   与**项目大脑**（§3 即时入库）；
3. 运行同步脚本把 U 层再生进本 skill（脚本在 `brain_core`）：
   `python "$BRAIN_CORE\code\86_sync_disciplines.py" --apply --ulayer-only`

5. **不得只写在对话里**（对话会被压缩/清空）。

### 6.2 为什么需要"同步脚本"而不是手动改
Skill 是静态文本。要让"任何子对话更新纪律"都能**回到底层**，唯一可靠的做法是：
**权威正文文件 + 一个能重新生成 skill 的脚本**，并在纪律里规定"改纪律必须跑同步"。
2026-10-15 起这条链完整为：`BRAIN_PROTOCOL.md`（权威层）→ `86_sync_disciplines.py --apply`（再生）

## 8. 三条最容易违反、且代价最大的纪律（**贴在眼前**）

1. **DOI / 引用标识一律不得凭记忆书写** —— 每一个都必须来自一次机器查询
   （Europe PMC `EXT_ID:<pmid>` / Crossref `/works/<doi>`），写完再打印全文清单目视比对。
   *（本项目实测：凭记忆写 5 个 DOI，错了 4 个。）*
2. **改"参数列表/接口/格式"这类代码，只过语法是不够的** —— 必须做**运行期验证**
   （把构造出的实参打印/求值出来确认）。*（本项目：同一处错误犯了两次，一次导致整批空跑。）*
3. **格式/接口类结论必须由一次端到端成功运行确认**，不能凭局部证据推断后当结论传播。
   *（本项目：3 条"已确认格式事实"全部是错的，且已写进文档与任务书。）*

## 9. 子代理监督（一旦开启子代理，自动进入）

- **开代理时立即注册**其预期产出路径 → 每轮检查活跃度（`mtime`/文件数变化）
- 判据：`OK`＝近期有活动｜`STARTING`＝尚无历史证据（不作判断）｜`STALL`＝静止≥12min（观察）｜
  **`SUSPECT`＝静止≥30min ⇒ 立即中断**
- 中断后：看工作目录证据 → 判断"卡死/死循环"还是"任务过大" → **接管或改范围后再决定是否重派（禁止原样重派）**
- **禁止只信子代理的汇报**：必须核对产出文件真实存在且非空，并抽查复算其数字
- 死循环五形态：反复重试同一失败命令｜反复下载同一资源｜文件数涨但净内容不变｜无限扩大检索不落盘｜无结论地反复"再验证一次"

> ⚠️ **§9 的"静止≥30 min 即中断"已被 §10.2 细化**（判据从"绝对时长"改为"**承诺的首个交付点是否兑现**"）。

## 10. ★★★★ 自动化工作流精髓（2026-09-21 实战提炼）

> **适用**：一旦任务要**开子代理 / 无人值守 / 多任务并行 / 长时间跑批**，本节即为操作纪律。
> **每条背后都有一次真实事故**（事故写在规则下方，便于理解"为什么不是教条"）。

### 10.1 任务书三要件（派活前必须写清，缺一不许开跑）

| 规则 | 可执行判据 |
|---|---|
| **A1 增量交付点** | 产出是"N 个同类物"（图/表/病例/算例）时，必须写"**先交 1 个并通过，再交 N−1 个**" |
| **A2 首个产物时限** | 必须写明"**X 分钟内落 `STATUS.txt` + 至少一个中间产物**"（短任务 10–15 min，长任务 20–30 min） |
| **A3 阶段间静默上限** | 长任务**每 30 分钟必须有一次落盘**；阶段之间不许连续静默 >30 min |

> **事故**：把"给用户看图"写成"交付一套阅图系统"（12 张 MPR + 3D + contact sheet + schema + 校验器 + 测试）⇒ 子代理 **30 分钟零落盘**，用户两次追问"为什么还没产出"。

### 10.2 判"卡死"的判据（**不要看时长**）

- **`running` ≠ 有进展**：`list_agents` 只说明它活着；**判进展必须看关注目录的文件新鲜度**。
- **判据 = 承诺的首个交付点是否兑现**；**任务书没写时限，是我的错**，不能只怪代理。
- **终止前先索要一次**（`STATUS.txt` + 快照）并给 20 min；仍无响应才终止。
- **终止 ≠ 取消**：必须**当场记入待跑队列**（用新格式任务书重派），**不许静默消失**。

> **事故**：两个任务跑了 **13 小时零产物**（其中一个是 13.5 h 的空目录），白占 2 核 2 槽位——而用户正在抱怨机器卡。

### 10.3 用户已有成熟工具时：交"地图"，**不要重造工具**

- 用户机器上若已有 Slicer / OpenFOAM / Excel / 商用求解器 ⇒ 优先交付「**定位 + 参数 + 步骤 + 每项的数字**」，让用户用**他的**工具；
- **不要**替他重造渲染/后处理/可视化。

> **事故**：我花力气做"阅图包"，而用户本可**在 Slicer 里三步**（加载 CTA → 加载 labelmap 并选 `LabelMap` → 勾选目标 label 右键 `Jump to center`）自己看。**真正有价值的交付物是"跳转地图 + 标签 id 表 + 方位核实步骤"。**

### 10.4 负载治理四步（用户报"机器卡"时）

1. **先量三个数**：**CPU% ｜ 内存余量 ｜ 目标盘 `% Idle Time`+队列长度**（报告里必须给这三项**实测值**，不得只说"已优化"）；
2. **先砍僵尸**（按 10.2 的判据）；
3. **给存活重活上节流**：并发 ≤1；`OMP/OPENBLAS/MKL/NUMEXPR/VECLIB=1`；求解器自身线程写死；**拉长写盘间隔**；每 10 min 写 `STATUS.txt`；预计 >2 h 的算例先报；
4. **重排优先级**：把**不需要大算例的部分**提前（口径核查、接口自洽检查、纯脚本任务）；**大算例推到夜间**。

- **分清"核瓶颈"还是"盘瓶颈"**：查物理盘映射（例 `Win32_PerfFormattedData_PerfDisk_PhysicalDisk`: `0 C: D:`｜`1 E: F:`｜`2 G:` ⇒ G 是独立盘，G 打满**不直接**拖慢 C:/D:）。
- **第三方常驻进程常常"看不见"**：内存小、无窗口 ⇒ 任务管理器要按**「累计 CPU 时间」**才看得见（实测：两个 `kcleaner.exe` 累计 **34.5 h / 28.7 h** ≈ 各占满 1 个核、已跑 2 天）。
- **代理杀不掉的（`Access is denied`）明确转用户**，不要反复尝试。

### 10.5 全盘搜索禁令

- **Git-Bash 下 `find /` 会遍历所有挂载盘**，且 `find` **没有提前退出机制**；
- **事故**：两条 skill 依赖检查触发的 `find /` **静默跑了 14 小时**，各烧约 **49,500 s CPU**，用户以为机器坏了；
- **纪律**：任何全盘搜索必须**限定路径 + `-maxdepth` + 超时**；跑批前确认没有遗留全盘扫描；**加机械化防线**（定时任务只杀"整盘 find 且存活 >5 min"的进程）。

### 10.6 ★★★ "静默错误族"：**跑出来看着对，其实是错的**

> **共同特征**：不报错、图好看、残差在降、`checkMesh` 通过 —— **只有专门的"账目"能抓**。

| 形态 | 实测例子 | 防线 |
|---|---|---|
| **单位二次换算** | 已是 SI 米制的点又 ×1e-3 ⇒ 入口剖面恒 0 ⇒ **零流量** | 从文件读几何/压力的路径**第一行断言量级**（如"入口直径必须落 1–40 mm"） |
| **自证式判据** | 判据 `Co ≤ 1` 被求解器设置 `maxCo=0.95` **自动保证** | 问："**我把设置改坏一点，它还会通过吗？**" 会 ⇒ 判据作废，改做**敏感度检验** |
| **算术平均冒充时均** | 自适应 dt 下**收缩期被过权 48%** | 时均**必须时间加权**（`∫Qdt/Δt`），并写明是哪种平均 |
| **多孔壁** | 壁面用 `zeroGradient` ⇒ 出口通量 = 入口 **15×**、壁面净漏 **33×**，而 `checkMesh` 与连续性误差**都不报** | 壁面 `noSlip` + **每例核验 `ΣQ_out ≈ Q_in`** |
| **容差陷阱（假失败）** | 暖启动下 `tol` 退化成绝对 1e-10，而残差舍入地板 ∝ 刚度尺度 ⇒ **误报"不收敛"** | 参考尺度与初值**解耦**；**"不收敛"必须先排除尺度/条件数** |
| **压力电平漏** | 出口 Dirichlet 压力电平 ⇒ 体积源（实测 **≈1.3 %/Pa**） | 建"**压力型出口 BC × 求解器能力**"对照表，按能力分工 |
| **跨表/跨段/单位错配** | 拿"升主动脉半径"比"肾上段平均直径" ⇒ 误判"几何不自洽" | **口径三问**：**同部位？同口径（半径/直径/面积/段平均）？同单位？** |
| **同源审计的虚假安全感** | "图像↔图像"的自洽审计**结构上不可能**发现跨表/跨段/单位混用 | 结论里**必须写明"本审计不覆盖 X"** |

### 10.7 每类数值工作的"第一道门"（过不了就不许出数）

- **CFD** ⇒ **通量账**：`ΣQ_out ≈ Q_in`（入口恒 0 或量级离谱 ⇒ **直接判无效**）。**"跑完 + 无报错 + 图好看"都不能代替它。**
- **FE 显式动力学** ⇒ 六项体检：**总质量 / 能量守恒 / 沙漏能 / 重跑一致性 / 约束秩 / 单元质量**。
- **逆问题/反演** ⇒ **控制组逐位复现基线** + 判据**事前冻结** + sha256。
- **文献参数** ⇒ **机器核验 DOI/PMID**；**允许"未检索到"，禁止估填**；**"首次/唯一"类措辞必须先做专门新颖性检索并留痕**。

### 10.8 "加性改动、默认不变"的五层证明模板

凡改共享代码（尤其被别人 import 的模块），改完必须能给这五层：

1. **bit-identical 冻结**：同进程打补丁前后，关键解析验证与解向量 `np.array_equal == True`；
2. **端到端字段级**：旧路径产物与权威 JSON **逐字段 `==`**；
3. **缓存键不变**（若系统有缓存）；
4. **新开关下与旧路径的差**（应在数值噪声量级）；
5. **判据冻结修订后复跑**，仍全等。

> 好处：**既敢改，又能证明"没把旧结论改坏"**。

### 10.9 判据伦理

- 判据**事前冻结**（JSON + sha256）；**FAIL 照记**；**不许事后回调容差**；
- 分歧必须给**归因**（离散/网格可比性/内迭代/口径），并说明"**是可比性前提未满足，不是代码互相矛盾**"；
- **"不收敛"必须与"物理上不可能"严格区分**；
- **允许自己推翻自己**，并**写死"作废条件"**（看到什么就撤回结论）。

### 10.10 子代理协作的现实约束（本环境实测）

- `send_message` 对子代理**经常不可用** ⇒ **要求报告自包含落盘**，并在最终消息给结论摘要；
- 父代理**能**用 `list_agents` + **文件新鲜度**监督；
- **子代理说"完成"必须核对产出文件真实存在且非空**，并**抽查复算其数字**；
- **同一个坑重复出现 ⇒ 升级为纪律**（实测：CFD 通量账在 Kratos / OpenFOAM 两侧同日各出一次）。

### 10.11 汇报纪律（每次子任务/子代理回馈后）

- 回复**末尾必须**列「**当前需要用户操作的事项**」，四段式：**①只有你能做的 ②可选/可延后（附我的绕法）③需要你拍板（附我的建议）④已闭环、无需操作**；
- **唯一事实来源 = 项目的「用户待做清单」文件**；**禁止凭记忆列**；
- 排序：**卡住下游最多者优先**；**30 秒能解锁一条轨道的永远排第一**。

## 11. ★★★★ 状态注入与"看得见的僵尸"（2026-10-16/17 实战提炼 · 来源：aorta_digital_twin）

> 触发事故：连续两轮回复漏了「第 0 步 / 打 beat / 双轨道状态 / 四段式」，被用户当场指出「没有按照最高逻辑执行」。

### 11.1 把"注入状态"做成【一条命令】，不是承诺
`code/8960_turn_boot.py` 这类脚本应一条命令输出六块：**第 0 步 exit code · 协议门 · §6 心跳/告警 · 磁盘哨兵 ·

### 11.2 僵尸的两种形态（★ 都会把"卡死检测"变成噪声）

   ★ **判据必须区分【当前】与【曾报】**：只有【当前】告警才阻塞；「曾报」只显示。
   ★ **修工具，不要清数据** —— 清一次下次还会留。

### 11.4 判据必须【正交】，不能拿"差不多"的量顶替
- ★ **反例**：「越出 ≤1 mm」曾被认为是"肺修进胸廓"的判据；但修后**三角真相交反而增加**
  ⇒ 该量只保证"顶点在骨外表面以内"、**不保证"不嵌在肋骨之间"**。**换 918 判内（点在实体内部）才分开好坏**：
  真例 **0.31–0.45% / 最深 0.00 mm**、坏的 **4.07% / 4.36 mm**。
- ★ **反例**：「三角真相交 = 0」当上界门是**方向错**的 —— 它计**接触面积**：真例中位 **98,229 对**、坏的只有 **13,075**
  ⇒ `=0` 判全人类不合格、`≤p95` 放过全部坏例。**两种都废**。
- ★ **通则**：★ **新判据必须先量【池内真例】的分布**，再看它能否把"已知坏"和"已真好"分开；
  ★ **方向可能整个反了**。

### 11.5 池比较的三条硬口径
1. ★ **必须降采样一致**（如 `arr[::2,::2,::2]`）：全分辨率对比会让池中位数从 98,229 变 **381,769**（7 倍假信号）。
2. ★ **必须按 QUARANTINE 排除**：**"取前 N 例"必然误用**（前 N 例恰是最先被封存的问题例）。
3. ★ **必须有 [池内 A/B 对半] 基线**：任何"我们的模型多好"的说法，都要和"同一池、模型重建自己"的天花板比。

### 11.6 "上游冻结"≠"上游没问题"
反例：某个结构自 vp31 起**逐字节冻结**，于是被判定"没人动过、所以没问题"；
真实情况是**它被冻结在一个本来就错的姿态里**，而**引入错误的那一步在更早的另一条线上**（换骨骼供体时从无"胸廓包住肺"的约束）。
★ **通则**：★ **"没改过"只能证明"不是你改坏的"，不能证明"它是对的"**；必须追到**【第一个把它放到错位的那一步】**。

### 11.7 "移植 == 重解"必须【真跑】，不能论证
反例被避免：把 A 线的修复搬到 B 线时，用"输入逐字节相同 + 确定性脚本"论证"等价"。
★ **正解**：**真跑一遍**，比**输出的 float32 字节**与**日志逐行**。
★ 附带教训：**整文件 sha256 是错尺**（npz 带 `meta`、`meta` 嵌了源路径）；**要比的是数值数组的字节**。

### 11.8 左手系：任何"法向/涡量/旋度"都要先声明坐标系
★★ **解剖系 `(x=左, y=前, z=上)` 是【左手系】**（左×前 = −上；DICOM LPS 才是右手系）。
★ **后果**：① **VTK 右手相机不 `fliplr` 就是镜像**（`相机在 −y` 只决定深度、`fliplr` 才决定左右，两者必须分开写）；
② **CFD 的叉积量（法向、涡量）会反号**。★ **方法学里必须写明坐标系。**

### 11.9 论文类工作：★ 证据账本先于正文
★ **正文可以等**（用户可能要求"等确定没问题再写"），但**账本必须持续积累**：
逐条记 `claim / status(有·等·空) / file / sha256 / value / control`。
★ **规矩**：`status="有"` 的条目**必须文件真实存在**；**随机抽 10 条核文件验数**；**发现已报的数互相矛盾 ⇒ 不许挑一个、要标"矛盾待裁"**。

## ★ §0am 阶段性反思纪律（2026-10-18 用户指令 · 每次阶段性交付后必做）

1. **以目标为导向**：引用用户原话，拆成 N1…Nk 可证伪必要条件，逐条对账（满足/未满足/部分，不许"基本满足"）。

   **口径冒充**（未拒绝当等价 / 重构当保真 / 批次当中心）、

3. **找错后先问"能否用现有资产 + 文献手段解决"**（不许直接重做）：必答现有资产逐项可复用性、文献里同行怎么做、≥2 条候选方案 + 代价。
