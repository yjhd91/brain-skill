# Brain：恢复与证据入口
权威：`./BRAIN_PROTOCOL.md`（U1–U29、§9 变更、§11 门控）。项目事实回项目原件；宿主/用户授权优先。本文件是目录不是摘要：DISCIPLINES_CORE 为生成索引，OPERATIONS 为条件细则，ASSET_RECOVERY 为本机绑定，均非平行权威。门 PASS 不等于恢复、遵守或完成。

## 0. 每轮三步
1 绑：确认绝对 root、cwd、记忆绑定，互不推定；错绑不写项目事实。
2 读：读 [操作](references/OPERATIONS.md) §12.15（约 5 千字符，**勿读全文**），再按它读主线、清单与回执。
3 报：每轮必出八项——技术部位·位置三问(P/R/S+子项)·路线图节点·分叉与回归·台账与回执·三级阶梯(L1逐项枚举)·四段式尾部·开工回执；判据见 §12.15，数字带证据路径与状态。
热读≤6000 字符，先扣入口与 brief 再按 §12.1 配给；超额逐条打印"仍超 N 字符"。索引只定位，任务输入必回原件核 hash、版本与口径。无资产变更的问答不扫描、不写盘。

## 1b. 资产脉络四问（2026-11-13 用户立 · 与 §1 同级 · 最高优先级）

**忽略资产属最高级别逻辑错误。** 每次引用任何资产（文件、记录、数值、目录）之前，必须答四问；任一答不出即报 UNKNOWN，不得宣告「没有」，不得宣告「已通过」。

| # | 问题 | 可查字段 |
|---|---|---|
| ① | 为什么落盘（谁生成、解决什么、什么条件下有效） | 生成脚本 + `produced_by` + 登记 |
| ② | 为什么放弃（有无作废/撤回/取代，理由为何） | `amendments` / `deprecated` / `withdrawn` / `superseded` / `corrected` |
| ③ | 是不是还在等别的东西（在等哪个前置） | `status` + `status_note` |
| ④ | 真实地位（现役/历史/占位/死路 四选一） | 前三问输出 |

- **标签不是地位**：`pass`/`fail`/`deprecated`/`latest`/目录名/记忆都不能代替四问。
- **同一名词可能对应多条互不相干的链**，按内容归链，不按目录名。
- **判断「有没有」必须按「日期 + 名词」全盘搜**，不得只看一个约定目录。
- **机械门优先**：存在清单 + 台账矛盾门（`contradicts_inventory` / `absent_claim_unverifiable` / `consumes_empty_asset`）是执行层；四问是解释层，两者都必须在。
- **事故来源**：2026-11-13 一天六次同类错误，共同形态是「读到一个标签就当事实」。

## 2. 状态与检索（2026-11-13 增）
- 空≠无匹配：未跑/预算耗尽/截断各须标记，不与"查过没有"同形（§12.2）。
- 命题三态：✓/✗/?，未验默认 ?；? 不作下游前提；收尾只报有界覆盖（§12.3）。
- 接缝刷新：失败、交接、压缩、换阶段后重读原件取回执；回忆不算刷新（§12.4）。
- 落盘双值：committed 与 accepted/pending 分记；未 committed 不得称收尾（§12.5）。
