# Brain：恢复与证据入口
来源：主动脉数字孪生实战（用户2026-09起要求）；2026-10建立brain_core；2026-10-25以U29细化既有U4/U7，并非此前无资产规则。

权威：`./BRAIN_PROTOCOL.md`（本仓随附全文）。项目事实回该项目原件；系统/宿主/用户授权优先。DISCIPLINES_CORE是生成索引，OPERATIONS是条件细则，均非平行权威。
**跨模型可恢复不保证模型遵守**：宿主须实际加载项目入口或brain。hash/协议门PASS不等于恢复或任务完成。

## 0. 实质轮与恢复轮
1. 确认目标绝对root、cwd、记忆绑定；不得互相推定。错绑不写项目事实，证据留目标项目授权目录。
2. 先读有界活跃目录的主线、原件路径、状态、缺口/下一步、失败/被推翻线索。热读总计≤6000字符；入口≤2000，brief分配≤4000，已加载不重复。禁止全文灌大目录/纪律。索引只定位，任务输入必回原件核来源/hash、版本/口径、验证状态；不默认从零开始。
3. OFFLINE（不可达）、MISSING（位置可达但缺件）、STALE（源/缓存指纹不符）分别报告；失败拒绝相关依赖动作。先当前、再历史/限定路径，每批≤12条，最多两批无新证据即报缺口，禁止盲扫。
4. 有变更：先落原件及来源/hash/验证→既有扫描→台账→检索索引→逐项核显式changed paths→brief/协议门；失败不得称收尾。mtime/件数不作证明。普通概念问答、无资产变更解释不扫描、不写盘。

- U26/U29：当前/历史分层留原路径/hash、替代、退役原因、失败经验；不删源件，不仅按新旧或无消费者判废，未接入须标注。
- 已授权能做的自主做；资源/账号/审批、专业判读、不可逆对外动作归用户。困难先查资产再查原始外部依据；DOI须机器核验，接口/格式须实跑。
- 改前备份、写后回读；长文本先write补丁脚本再shell只运行，不用python -c/heredoc；遵守临时盘/禁区，禁止git add -A/.

## 3. 规则变更与收工
改规则先读权威§9：新版本/备份→登记→docs说明→显式提交；用户要求待提交则如实标记。完整源在本仓 `brain/`（入口 + 协议 + 纪律索引）；本机同步/部署仪器（86/87）不随公开仓发布；安装件不是孤本。旧§0恢复义务由本入口接管。
证据报结果/覆盖/未覆盖/风险，行数字节不是能力证明。交接留目标项目内单一状态载体。需用户事项据项目待做原件分四段：只有用户能做、可延后及绕法、需拍板及建议、已闭环。
